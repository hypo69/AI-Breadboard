# Техническое задание: Веб-интерфейс «Отслеживание активности процесса» (Process Intelligence & Activity Deep Dive)

## 1. Назначение и ключевая концепция

Настоящее техническое задание определяет требования к проектированию и разработке специализированной веб-вкладки **«Отслеживание активности процесса» (Process Activity Deep Dive)** в рамках веб-интерфейса платформы **AI-Breadboard Windows Diagnostic & Administration Center**.

### 🔑 Решение проблемы PID Recycling (Переиспользование PID)
В ОС Windows идентификатор процесса (`PID`) является динамическим короткоживущим ресурсом, который переназначается операционной системой сразу после завершения процесса. Отслеживание истории исключительно по `PID` приводит к смешиванию метрик разных программ.

Вкладка строится на архитектурном принципе **Process Intelligence** (согласно стандарту `pid.txt`):
* **Базовый объект отслеживания**: Единичный инстанс процесса (`process_instance`) с уникальным первичным ключом `instance_id`.
* **Гарантия уникальности**: Параметр `start_time` (время создания процесса от ядра ОС) в комбинации с `PID` формирует уникальную пару `UNIQUE(pid, start_time)`.
* **Точность связей**: Дочерние процессы привязываются к родителю через `parent_instance_id`, что полностью исключает фантомные связи при переиспользовании PID системой.

## 2. Модель данных и архитектура бэкенда

Бэкенд предоставляет данные веб-интерфейсу на основе трехзвенной схемы SQLite (`telemetry.db`):

```text
process_definition  (Паспорт программы)    -->  python.exe, путь, SHA256, иконка
        │
process_instance    (Конкретный запуск)   -->  instance_id=18472, PID=7316, start_time, exit_time, exit_code
        │
process_sample      (Срезы во времени)    -->  CPU, RAM, GPU, Disk, Sockets, File Events по instance_id
```

### Схема таблицы `process_instance`
```sql
CREATE TABLE IF NOT EXISTS process_instance (
    instance_id INTEGER PRIMARY KEY AUTOINCREMENT,
    definition_id INTEGER NOT NULL,
    pid INTEGER NOT NULL,
    parent_instance_id INTEGER,
    name TEXT NOT NULL,
    executable_path TEXT NOT NULL,
    command_line TEXT,
    start_time TEXT NOT NULL,
    exit_time TEXT,
    exit_code INTEGER,
    session_id INTEGER DEFAULT 1,
    user_name TEXT,
    integrity_level TEXT,
    status TEXT NOT NULL DEFAULT 'RUNNING', -- 'RUNNING', 'EXITED', 'SUSPENDED'
    UNIQUE (pid, start_time),
    FOREIGN KEY (parent_instance_id) REFERENCES process_instance(instance_id)
);
```

## 3. Архитектура и UI/UX макет веб-вкладки

Интерфейс вкладки разделен на **7 функциональных виджетов**, обеспечивающих 360-градусный обзор активности выбранного инстанса процесса.

### 3.1 Панель выбора и профиля инстанса (Instance Header & Selector Bar)
* **Селектор процесса**:
  * Выпадающий список активных процессов с быстрым поиском по имени, PID или `instance_id`.
  * Переключатель режимов: `«Активные процессы»` / `«Завершенные инстансы (История)»`.
* **Карточка профиля**:
  * Иконка приложения, `Имя процесса`, `PID`, `instance_id`.
  * Статус инстанса: цветовой бейдж (`RUNNING` — зеленый, `EXITED` — серый c кодом выхода `exit_code: 0`, `SUSPENDED` — желтый).
  * Временные метки: Время запуска (`start_time`), Время работы (Uptime / Duration).
  * Системный контекст: Имя пользователя, SID, Уровень привилегий UAC (`IntegrityLevel`), Полная командная строка запуска (`CommandLine`).

### 3.2 Метрики ресурсоемкости в реальном времени (Real-Time Metrics Charts)
Четыре синхронизированных интерактивных графика временных рядов (фильтрация по `instance_id`, выводимые интервалы: 1 мин, 5 мин, 1 час, 24 часа):
1. **ЦП (CPU Utilization)**: % загрузки процессора с цветовой разбиением на `User Time` и `Kernel Time`, динамический счетчик потоков (`thread_count`).
2. **Память (RAM Profile)**: График физической памяти (`Working Set` в МБ), выделенной виртуальной памяти (`Private Bytes` в МБ) и счетчик ошибок адресации страниц (`Page Faults/sec`).
3. **Графический процессор (GPU & VRAM)**: Использование выделенной VRAM (МБ) и % загрузки графических движков (3D / Compute).
4. **Дисковый I/O**: Скорость чтения и записи данных (КБ/с, МБ/с) и количество операций ввода-вывода (IOPS).

### 3.3 Иерархическое дерево происхождения (Process Lineage & Hierarchy Graph)
* Интерактивная граф-схема предков и потомков текущего процесса на основе `parent_instance_id`:
  ```text
  explorer.exe (PID 1800, #100)
      └── Code.exe (PID 4200, #101)
            └── python.exe (PID 7316, #102)  <-- [Текущий инстанс]
                  └── python.exe (PID 8124, #103)
  ```
* Клик по любому узлу графа мгновенно переключает весь веб-интерфейс на анализ выбранного инстанса.

### 3.4 Таблица сетевых сокетов и соединений (Network Sockets Panel)
* Список открытых сокетов, принадлежащих `instance_id`:
  * Протокол (`TCP`/`UDP`), Локальный адрес и порт $\rightarrow$ Удаленный IP-адрес и порт.
  * Статус соединения (`ESTABLISHED`, `LISTEN`, `CLOSE_WAIT`).
  * Скорость передачи данных (Отправка / Прием в КБ/с).
  * DNS-имя и страна назначения (GeoIP).

### 3.5 Лента файловых операций (File Events Feed)
* Журнал операций с файлами в отслеживаемых папках, инициированных данным `instance_id`:
  * Табличная лента: Время $\mid$ Действие (`CREATE`, `MODIFY`, `DELETE`, `RENAME`) $\mid$ Целевая папка $\mid$ Полный путь к файлу $\mid$ Объём байт.
  * Фильтр по типу операции и быстрый поиск по расширению файла (`.json`, `.dll`, `.log`).

### 3.6 Панель ресурсов ОС и системных дескрипторов (Handles & GUI Objects)
* Графические индикаторы использования ресурсов ядра Windows:
  * **Process Handles Count**: Количество открытых дескрипторов (файлы, секции, мутексы).
  * **GDI Objects**: Количество объектов графического интерфейса (кисти, шрифты, битмапы).
  * **USER Objects**: Количество оконных дескрипторов и меню.
  * *Индикатор риска*: Детектор утечек (автоматическое предупреждение при аномальном росте GDI/USER объектов).

### 3.7 Панель безопасного администрирования (SafeOps Action Panel)
* Панель действий с подтверждением диалоговым окном:
  * **Завершить процесс (`Kill Process`)**: Вызов `TerminateProcess` с записью причины в лог.
  * **Приостановить / Возобновить (`Suspend / Resume`)**: Заморозка всех потоков процесса.
  * **Снять дамп памяти (`Create Memory Dump`)**: Сохранение `.dmp` файла в директорию дампов.
  * **Изменить приоритет (`Set Priority Class`)**: Переключение приоритета CPU (Low, Normal, High, Realtime).

## 4. Спецификация REST API Контрактов (FastAPI)

Все эндпоинты работают строго с идентификатором `instance_id` и обеспечивают время отклика < 5 мс за счет SQLite индексов.

### 4.1 `GET /api/v1/telemetry/instances/active`
Получение списка всех активных процессов текущей сессии.
* **Response**: `[{"instance_id": 18472, "pid": 7316, "name": "python.exe", "cpu_percent": 12.4, "memory_mb": 320.5, "start_time": "..."}]`

### 4.2 `GET /api/v1/telemetry/instances/{instance_id}`
Получение подробного паспорта и текущего статуса инстанса.

### 4.3 `GET /api/v1/telemetry/instances/{instance_id}/samples`
Получение временного ряда метрик (CPU, RAM, GPU, IO) за выбранный интервал.
* **Params**: `from_time`, `to_time`, `limit` (default: 300).

### 4.4 `GET /api/v1/telemetry/instances/{instance_id}/lineage`
Получение дерева предков и потомков инстанса.

### 4.5 `GET /api/v1/telemetry/instances/{instance_id}/file-activity`
Получение файловых событий по `instance_id`.

## 5. Требования к обновлению данных и UI-производительности

1. **Режим обновления чартов**: Автоматический опрос REST API каждые 1.0 сек для активных инстансов.
2. **WebSocket / SSE Канал**: Для мгновенного стриминга ленты файловых событий (`process_file_events`) и сетевых подключений без нагрузки на HTTP-поллинг.
3. **Кэширование завершенных инстансов**: Завершенные процессы (`status = 'EXITED'`) прекращают поллинг и отображаются в статическом режиме анализа истории.
