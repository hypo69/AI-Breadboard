## 1. Архитектурная модель Command Registry и SafeOps

В AI-Breadboard консольные утилиты интегрируются через интерфейс `SafeOps` с категоризацией по уровням риска:

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                       AI Diagnostics & Orchestrator                     │
└─────────────────────────────────────────────────────────────────────────┘
                                     │ Запрос действия
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                         Windows Command Registry                        │
│ ├── Валидация аргументов (Whitelisting / Регулярные выражения)          │
│ ├── Уровень риска (READ_ONLY / LOW / MEDIUM / HIGH / CRITICAL)          │
│ ├── Проверка прав (Standard / Administrator / SYSTEM)                   │
│ └── Режим Dry-Run / Симуляция изменений                                 │
└─────────────────────────────────────────────────────────────────────────┘
                                     │ Исполнение
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      SafeOps Execution Engine                           │
│ ├── Неинвазивный режим: Сбор данных через Native API / WMI / Subprocess │
│ ├── Инвазивный режим: Обязательная точка отката (System Restore / VSS)  │
│ └── Потоковый парсинг вывода (JSON / Таблицы / Регулярные выражения)   │
└─────────────────────────────────────────────────────────────────────────┘
```

## 16. Матрица: утилиты без удобных/прямых API-аналогов

Следующие консольные утилиты **обладают наивысшей ценностью** для AI-Breadboard, так как их функционал либо не имеет открытого Win32 C/C++ API, либо требует сотен строк сложного недокументированного NT/COM-кода:

| Утилита | Ключевая ценность для AI-Breadboard | Сложность реализации через чистый API | Применение в приложении |
|---|---|---|---|
| **`reagentc.exe`** | Управление и статус среды WinRE | 🔴 **Критическая**: Нет публичного C++ API | Диагностика аварийного восстановления |
| **`powercfg /batteryreport` & `/energy`** | Полный детальный профиль износа батареи и энергопотребления | 🔴 **Критическая**: Анализ сотен метрик ETW и ACPI | Hardware Telemetry & Health Analyzer |
| **`powercfg /requests`** | Мгновенный список блокировок сна (драйверы, аудио, процессы) | 🟡 **Высокая**: Требует парсинга структур `PowerInformation` | Sleep Trouble Shooter |
| **`sfc.exe /scannow`** | Верификация хэшей сотен тысяч системных файлов по каталогам WRP | 🔴 **Критическая**: Закрытый протокол Windows Resource Protection | Integrity & Repair Collector |
| **`pnputil /enum-devices /problem`** | Мгновенный фильтр всех аппаратных устройств с ошибками Code 10/43 | 🟡 **Высокая**: Требует полного рекурсивного обхода дерева SetupAPI | Device & Hardware Inspector |
| **`wevtutil epl`** | Надежный бинарный экспорт каналов в `.evtx` | 🟡 **Средняя**: Быстрее и надежнее для больших объемов | Log Intelligence & Archiver |
| **`manage-bde -status`** | Четкий статус шифрования, TPM, PIN и готовности томов | 🟡 **Средняя**: Проще WMI в сценариях pre-boot | Security Baseline Monitor |
| **`fsutil behavior query`** | Проверка TRIM для SSD, Disable8dot3NameCreation, LargeSystemCache | 🟡 **Средняя**: Множественные вызовы `DeviceIoControl` | Storage Optimization Advisor |
