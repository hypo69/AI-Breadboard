⚙️ Режимы работы (config.json → rag.mode)
  • rag+model (Гибридный / Основной): Сначала проверяется локальная медиатека. Если фильм найден — LLM красиво рассказывает о нём со ссылкой на наличие в медиатеке. Если фильм отсутствует — LLM обращается к веб-поиску (MCP/Grounding) и рассказывает о фильме с кнопкой загрузки <film>.
  • rag (Строгий локальный): Работает только по базе media.db. При отсутствии тайтла выдаёт чёткое «В локальной базе не найдено» без ложных подстановок.
  • model (Без базы): Прямой ответ LLM и веб-поиск без обращения к дискам.
📊 Сценарии обработки
Сценарий Пример Алгоритм Результат
Фильм есть в базе «Расскажи о фильме А зори здесь тихие» Точный поиск в media.db (Score 1.0) / FAISS ≥ 0.60 → контекст в LLM LLM сообщает, что фильм доступен в медиатеке, описывает сюжет и тегирует <film>.
Фильма нет в базе «Расскажи о сериале Сваты» Локальный RAG даёт 0 совпадений → Fallback на Web Search (MCP) LLM рассказывает о сериале, указывает, что его нет на дисках, тегирует <film> для торрентов.
Команда запуска «Включи А зори здесь тихие» Проверка пути на диске → WebSocket play_file_by_path Мгновенный старт в плеере (Direct Play).
Подборка / Настроение «Найди боевик на вечер» Извлечение подходящих жанров → LLM формирует диалоговую подборку Живая рекомендация с обоснованием «почему стоит посмотреть».
🎯 Порог косинусного сходства (Cosine Similarity)

Для исключения ложных срабатываний порог в rag_search_tool установлен на 0.60. Запросы с более низким сходством считаются отсутствующими в локальной базе и корректно перенаправляются в интернет-поиск.
