# Шаблон заголовка файла проекта

## Общие требования
- **Все заголовки** должны быть на русском языке.
- **Главный принцип поля `Description` — исчерпывающий контекст без необходимости читать код:**
  - Описывать не только **ЧТО** делает код, но в первую очередь **ЗАЧЕМ** он это делает (архитектурные цели: производительность, отказоустойчивость, предотвращение дедлоков/блокировок, fail-safe).
  - Обязательно раскрывать **все режимы работы / флаги** (например, режимы буферизации `memory`, `file`, `direct`), ключевые сайд-эффекты и жизненный цикл данных.
  - Разработчик при открытии файла должен получить полное понимание роли модуля и вариантов его поведения прямо из шапки.
- Должен присутствовать блок `Description`, `Location in project tree` (или метаданные), `Dependencies`, `Usage example` (с полными рабочими параметрами/DI) и мета‑информация (author, copyright, updated).
- Формат заголовка должен соответствовать стилю, используемому в `ENGINEERING.md` и `GEMINI.md`.

### Как использовать шаблон
1. Скопируйте блок кода выше в начало нового `.py`‑файла.
2. Заполните `Description`, подробно раскрыв:
   - **Зачем** написан этот код и какие проблемы архитектуры он решает.
   - **Какие режимы/сценарии** он поддерживает.
3. Укажите корректный пример вызова в `Usage Examples` с явной передачей всех необходимых зависимостей (Dependency Injection).
4. **Обязательное правило при модификации**: Каждый раз, когда вносится изменение в код файла, в шапке файла **MUST** обновляться поле `Updated` с актуальной датой и временем изменения (`Updated: YYYY-MM-DD HH:MM:SS`).

### Пример готового заголовка
```python
# -*- coding: utf-8 -*-
# =============================================================================
# Process Name: AI-Breadboard Apps Windows Telemetry Sqlite - Buffer
# =============================================================================
# Description:
#   Управление буферизацией и пакетной записью (batching) потока телеметрии в SQLite.
#
#   Зачем нужен этот модуль:
#     1. Снижение нагрузки на диск (I/O) и ускорение SQLite:
#        Объединяет одиночные события метрик в пачки, выполняя одну быструю
#        транзакцию вместо сотен мелких операций записи с частыми fsync/commit.
#     2. Предотвращение блокировок базы данных:
#        Минимизирует время удержания эксклюзивных транзакций SQLite, предотвращая
#        ошибки 'database is locked' при одновременном чтении данных агентами и UI.
#     3. Защита от потери данных (Fail-Safe / Disaster Recovery):
#        При сбоях записи или аварийном завершении удерживает данные во внешнем
#        журнале и автоматически восстанавливает/дописывает их при следующем старте.
#
#   Поддерживаемые режимы буферизации (buffer_mode):
#     - 'memory' (По умолчанию):
#         Накапливает записи в оперативной памяти (список в RAM).
#         Сброс в БД происходит по достижении buffer_size или по таймеру flush_interval_seconds.
#     - 'file':
#         Каждая входящая запись немедленно сериализуется и дописывается на диск
#         в аварийный JSONL-файл (telemetry_buffer.jsonl) с вызовом fsync.
#         Защищает от потери данных при внезапном падении процесса/питания.
#     - 'direct':
#         Отключает фоновый периодический таймер автосброса. Записи накапливаются в RAM
#         и сбрасываются только при заполнении buffer_size или явном вызове flush().
#
# Usage Examples:
#   Python API:
#     from apps.windows.telemetry.sqlite.buffer import TelemetryBuffer
#     from apps.windows.telemetry.sqlite.connection import TelemetryConnectionManager
#     from apps.windows.telemetry.sqlite.writer import TelemetryWriter
#
#     cm = TelemetryConnectionManager("telemetry.db")
#     writer = TelemetryWriter(cm)
#     buf = TelemetryBuffer(
#         connection_manager=cm,
#         writer=writer,
#         buffer_mode='memory',
#         buffer_size=50,
#         flush_interval_seconds=30.0
#     )
#     buf.enqueue({"timestamp": "...", "cpu_percent": 12.5})
#
# File: buffer.py
# Project: ai-breadboard
# Package: apps.windows.telemetry.sqlite
# Author: hypo69
# Copyright: © 2026 hypo69
# Updated: 2026-10-05 23:55:00
# =============================================================================
```
