## 1. Общие принципы документирования

### 1.1 Документирование — это часть кода
- **Документация пишется одновременно с кодом**, а не после.
- Каждая function и class **MUST** содержать docstring перед развёртыванием.
- Docstrings — это **part of the code**, а не опциональный комментарий.

### 1.2 Три уровня документирования
| Уровень | Описание | Где |
|---------|----------|-----|
| **1. Docstring** | Описание функции/класса, Parameters, результаты, Examples | В коде функции |
| **2. Комментарии** | Пояснение логики "почему", а не "что" | В критических местах кода |
| **3. README.md** | Описание модуля, архитектура, использование | В директории модуля |

### 1.3 Правило "One Document Per Module"
Каждая директория проекта **MUST** содержать **README.md** на русском языке, описывающий:
- Назначение модуля
- Основные компоненты
- Examples использования
- Ссылки на связанные модули

## 2. TDD-документирование (Mandatory Workflow)

### 2.1 Когда использовать TDD-doc-gen
**TDD-документирование обязательно (MANDATORY) в следующих случаях:**

1. ✅ **Добавление нового функционала** — новые функции, классы, методы
2. ✅ **Изменение сигнатуры функции** — добавление/удаление параметров, изменение типов
3. ✅ **Изменение логики функции** — переписывание алгоритма, изменение результата
4. ✅ **Добавление новой директории** — создание модуля, пакета
5. ✅ **Рефакторинг** — переименование функций, перемещение кода между файлами

### 2.2 Процесс TDD-doc-gen (Правильный порядок)


## 3. Структура docstring для функций и классов

### 3.1 Единый формат docstring (hypo69 Docblock Standard)

**Обязательный порядок секций:**

```text
Краткое описание (1 string)

Полное описание (опционально, 2-3 предложения)

Args:
    param_name (type): Описание параметра и его назначение.
                       Значение по умолчанию: default_value.

Returns:
    type: Описание возвращаемого значения.

Exceptions:
    ExceptionType: Условия возникновения исключения.

Examples:
    >>> import module
    >>> result = function(param1, param2)
    >>> print(result)
    expected_output
```

### 3.2 Правила для секций

#### **Args:**
- **MUST** содержать все Parameters функции
- Порядок параметров совпадает с сигнатурой функции
- Для каждого параметра: тип в `(круглых скобках)`, описание, значение по умолчанию
- Типы записываются стандартом Python typing: `int`, `str`, `Optional[Dict]`, `List[str]`

**Пример:**
```python
Args:
    timeout (int): Максимальное время ожидания в секундах.
                   Значение по умолчанию: 30.
    retry_count (Optional[int]): Количество повторных попыток.
                                 Значение по умолчанию: 0.
```

#### **Returns:**
- Описывает тип и назначение возвращаемого значения
- Если function Returns `False` при ошибке, указать это явно
- Для `Self` (для методов цепочки): `Self: Текущий экземпляр класса`

**Пример:**
```python
Returns:
    bool: True при успешном выполнении, False при ошибке или невалидных входных данных.
    
Returns:
    Dict: Dictionary с ключами 'name', 'age', 'email' или empty {} при ошибке.
```

#### **Exceptions:**
- Перечисляет все типы исключений, которые может выбросить function
- Описывает условие, при котором выбрасывается exception
- Опускается, если function не выбрасывает исключения

**Пример:**
```python
Exceptions:
    ValueError: Если параметр timeout <= 0.
    ConnectionError: Если не удалось подключиться к серверу в течение timeout секунд.
    FileNotFoundError: Если указанный путь не существует.
```

#### **Examples:**
- **MUST** содержать работающий, скопируемый код
- Минимально 1 пример
- Использовать `>>>` для кода Python REPL
- Показать ожидаемый результат без `>>>` перед ним

**Пример:**
```python
Examples:
    >>> from core.ai import UnifiedChatModel
    >>> model = UnifiedChatModel(model_name='gemini-2.0-flash')
    >>> response = model.chat('Привет, мир!')
    >>> print(len(response) > 0)
    True
```

### 3.3 Docstring для классов

**Структура:**

```python
class MyClass:
    """Краткое описание класса.
    
    Полное описание роли класса в системе, его архитектурное место.
    
    Attributes:
        attr_name (type): Описание публичного атрибута класса.
        _private_attr (type): Описание приватного атрибута.
    
    Examples:
        >>> obj = MyClass(param='value')
        >>> obj.method()
        result
    """
```

## 4. Документирование директорий (README.md)

### 4.1 Обязательное содержание README.md

**Каждая директория (кроме служебных) MUST содержать README.md с:**

1. **Заголовок** — Название модуля
2. **Назначение** — Что делает этот Module, его роль в проекте
3. **Архитектура** — Ключевые компоненты, диаграмма (если нужна)
4. **API** — Основной интерфейс использования
5. **Examples** — Код с примерами использования
6. **Связанные модули** — Ссылки на зависимости и связанные файлы
7. **Файловая структура** (для сложных модулей)

### 4.2 Шаблон README.md для модуля

```markdown
# Название модуля

**Description:** Краткое описание функции модуля (15-25 слов).

## Архитектура

Основные компоненты:
- `file1.py` — Class `ClassName`, отвечает за X
- `file2.py` — Function `function_name()`, отвечает за Y

```
┌─────────────────┐
│   Component A   │
└────────┬────────┘
         │ uses
┌────────▼────────┐
│   Component B   │
└─────────────────┘
```

## Использование

### Базовый пример

\`\`\`python
from core.module import ClassName

obj = ClassName(param='value')

print(result)
\`\`\`

## Файлы

- `__init__.py` — Экспорт публичного API
- `main.py` — Основная логика
- `utils.py` — Вспомогательные функции

## Ссылки

- [`../../DOCUMENTATION_INDEX.md`](../../DOCUMENTATION_INDEX.md) — Главный индекс

```

### 4.3 Исключения (когда README.md НЕ нужен)

- `tmp/`, `tests/`, `tools/` — служебные папки (SHOULD иметь README для сложных случаев)

## 5. Examples и best practices

### 5.1 Полный пример документированной функции

```python
def calculate_file_size(file_path: Optional[str] = '', timeout: Optional[int] = 10) -> int:
    """Вычисление размера файла в байтах.
    
    Function receives размер файла через систему, processes ошибки файловой системы
    и Returns результат в байтах. При ошибке Returns 0.
    
    Args:
        file_path (Optional[str]): Абсолютный или относительный путь к файлу.
                                    Значение по умолчанию: ''.
        timeout (Optional[int]): Максимальное время ожидания операции в секундах.
                                Значение по умолчанию: 10.
    
    Returns:
        int: Размер файла в байтах или 0 при ошибке/несуществовании файла.
    
    Exceptions:
        OSError: Если операционная система не позволяет прочитать метаданные файла.
        PermissionError: Если нет прав доступа к файлу.
    
    Examples:
        >>> size = calculate_file_size('/path/to/file.txt')
        >>> print(size > 0)
        True
        
        >>> # Несуществующий файл Returns 0
        >>> size = calculate_file_size('/nonexistent/file.txt')
        >>> print(size)
        0
    """
    # Check входных параметров (Early Return)
    if not file_path:
        return 0
    
    try:
        return Path(file_path).stat().st_size
    except (FileNotFoundError, PermissionError) as ex:
        logger.error(f"Не удалось получить размер файла: {file_path}", ex, exc_info=True)
        return 0
```

```python
    Attributes:
        db_path (str): Абсолютный путь к файлу БД (по умолчанию: 'media.db' в рабочей директории).
        connection (sqlite3.Connection): Объект подключения к БД.
    
    Examples:
        >>> db = MediaDatabase(db_path='./data/media.db')
        >>> db.initialize()
        >>> media_list = db.get_all_media()
        >>> print(len(media_list) > 0)
        True
    """
    
    def __init__(self, db_path: Optional[str] = '') -> None:
        """Initialization объекта базы данных.
        
        Args:

        Examples:
            >>> db = MediaDatabase(db_path='./media.db')
        """

            sqlite3.Error: При критических Errorх работы с БД.

        """
```
