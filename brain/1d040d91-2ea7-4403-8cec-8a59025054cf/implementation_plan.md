# Удаление модуля `src/logger`

## Цель

Пользователь запросил удаление модуля `src/logger`, поскольку в корне проекта уже есть готовый логгер (пакет `logger`). Мы заменим все импорты `src/logger` на этот корневой логгер и полностью удалим совместимый слой.

## Требуется согласование пользователя

> [!IMPORTANT] **Критический вопрос**
> `src/logger` импортируется более чем в 200 местах проекта. Полная замена импорта и удаление модуля — крупное изменение, которое может нарушить работу, если не будет выполнено полностью.

## Открытые вопросы

- Подтверждаете ли вы использование корневого пакета `logger` (файл `logger/logger.py`) в качестве единственного логгера?
- Нужно ли сохранять текущий формат логов (цветные консольные выводы, ротацию, JSON) и совместимый API (вызовы `logger.error(msg, ex, False)` и т.п.)? При необходимости добавим thin‑wrapper в корневом пакете.

## Предлагаемые изменения

### 1. Подготовка совместимого глобального логгера (при необходимости)
- Если текущий логгер в `logger/logger.py` уже предоставляет нужный API, добавляем небольшую обёртку, сохраняющую совместимость со старым вызовом `logger.error(msg, exc, suppress_console: bool = False)`. Это позволит не менять вызовы в коде.
- При необходимости обновляем конфигурацию логгера (цвет, ротация, JSON) в `logger/logger.py`.

### 2. Замена импортов
- Во всех файлах, где сейчас `from src.logger.logger import logger` или `from src.logger import logger`, заменить импорт на `from logger import logger`.
- В файлах, где используется короткий импорт `from logger import logger` (из пакета `src/logger`), также заменить на импорт из корневого пакета.
- Обновить любые относительные импорты, если они есть, чтобы они указывали на новый путь.

### 3. Удаление модуля `src/logger`
- После полной замены импортов и успешного прохождения тестов удалить каталог `src/logger` и все его файлы (`logger.py`, `header.py`, `compress_logs.py`, `log_analyzer.py`, `conftest.py`, `README.MD`).
- Обновить документацию проекта, убрав раздел о `src/logger`.

### 4. Тесты и проверка
- Запустить полный набор тестов `pytest tests/ --cov`.
- Добавить новые тесты, проверяющие, что импорт `from logger import logger` работает во всех модулях и сохраняет прежнее поведение.
- Убедиться, что приложение стартует без импортных ошибок и логирует корректно.

## План проверки

### Автоматические тесты
- `pytest tests/ --cov` – убедиться, что покрытие не падает ниже текущего порога.
- Специфический тест на импорт `logger` из разных модулей.

### Ручная проверка
- Запустить приложение (`py manage_tools.py run`) и убедиться, что в консоль выводятся логи, а файлы логов создаются корректно.
- Проверить, что сохранённый формат (цветные сообщения, JSON) остаётся.

*Если пользователь одобрит план, мы начнём выполнение, начиная с проверки совместимости корневого логгера и замены импортов.*
