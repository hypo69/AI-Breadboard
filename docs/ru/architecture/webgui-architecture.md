# 🖥️ Архитектура веб-интерфейса и системы шаблонов (WebGUI)

## 📌 Обзор

Веб-интерфейс **AI-Breadboard** спроектирован по модульной компонентной архитектуре. Каждая страница системы (`/` — главный интерфейс, `/admin` — панель управления, `/tc` и `/apps` — тестовый стенд и каталог приложений) представляет собой легковесную **оболочку (Shell)**, в которую динамически загружаются и монтируются независимые **шаблоны вкладок (Tabs)**.

Управление навигацией, переключением панелей, жизненным циклом и делегированием событий стандартизировано через единый диспетчер [`src/api/webgui/js/tab-core.js`](file:///c:/Users/onela/AppData/Local/AI-Breadboard/src/api/webgui/js/tab-core.js).

## ⚙️ Модульная система шаблонов (Micro-Templates)

Каждая вкладка в системе изолирована в отдельной папке `src/api/webgui/<name>_tab/` и состоит из:
1. **`index.html`**: фрагмент разметки с корневым контейнером, модальными окнами и элементами управления.
2. **`main.js`**: функциональный скрипт, подключающий API-эндпоинты и регистрирующий глобальный lifecycle-хук `window.init<Name>Tab()`.
3. **`README.md`**: описание назначения, зависимостей и контракта вкладки на русском языке.

### Контракт DOM и правила именования

| Элемент | Контракт / Атрибут | Пример |
|---|---|---|
| **Кнопка переключения** | `data-tab="tab-<name>"` (или `data-tab="<name>"`) | `<button data-tab="tab-about-system">О системе</button>` |
| **Контейнер содержимого** | `id="tab-<name>"` с классом `tab-pane fade` | `<div id="tab-about-system" class="tab-pane fade"></div>` |
| **Общий родитель вкладок** | `id="mainTabContent"` с классом `tab-content` | `<div class="tab-content" id="mainTabContent">` |
| **Бейдж активного раздела** | `id="active-tab-title-badge"` | Автоматически принимает иконку и текст активной кнопки |
| **Выдвижное меню (Offcanvas)** | `id="leftSideNavOffcanvas"` / `appsSideNavOffcanvas"` | Автоматически скрывается после выбора раздела |

## 🔄 Диспетчер `tab-core.js` и Жизненный Цикл

Диспетчер [`tab-core.js`](file:///c:/Users/onela/AppData/Local/AI-Breadboard/src/api/webgui/js/tab-core.js) предоставляет унифицированный API:

```javascript
import { switchTab, loadTab, setupTabClicks } from '/html/js/tab-core.js';

// 1. Асинхронная загрузка шаблона и скрипта вкладки
await loadTab('about-system', '/about_system_tab/index.html', '/about_system_tab/main.js');

// 2. Переключение на вкладку с обновлением URL-хэша (#tab-about-system)
switchTab('tab-about-system');

// 3. Единое глобальное делегирование кликов (вызывается один раз при старте оболочки)
setupTabClicks();
```

### Алгоритм работы `switchTab`:
1. Находит все элементы с атрибутом `[data-tab]`, снимает класс `active` и устанавливает его строго на целевую кнопку.
2. Находит все блоки `.tab-pane` внутри `#mainTabContent`, скрывает неактивные и активирует целевой контейнер (добавляет классы `show active`).
3. Синхронизирует разметку бейджа `#active-tab-title-badge`.
4. Закрывает открытые экземпляры Bootstrap Offcanvas.
5. Записывает `#tab-<name>` в `history.replaceState`.
6. Вызывает динамический lifecycle-хук `window[`init${PascalCaseName}Tab`]?.()`.

## 🛡️ Стандарты верстки и предотвращение аномалий отображения

Для предотвращения сбоев верстки (например, эффекта «черного экрана» или растягивания неактивных вкладок на весь экран `100vh`) установлены обязательные правила:

1. **Единственность активного состояния при загрузке:**
   - В статическом HTML оболочек (`index.html`) только **одна** кнопка и **один** `.tab-pane` могут иметь класс `active` / `show`.
   - Не допускается одновременное указание `active` на кнопках верхнего уровня и вложенных пунктах выпадающих меню (Dropdown).

2. **Изоляция размеров для неактивных контейнеров:**
   - Специфические CSS-правила высоты (например, `min-height: 80vh`, `height: calc(100vh - 55px)` для чата) применяются **строго** с селектором `.active` (например, `#tab-chat.active`).
   - Для неактивных панелей `.tab-pane:not(.active)` гарантируется `display: none`.

3. **Размещение всплывающих окон (Modals):**
   - Модальные окна (`.modal.fade`) внутри шаблонов вкладок должны инициализироваться через Bootstrap Modal API без прямого влияния на поток документа в нормальном состоянии.
