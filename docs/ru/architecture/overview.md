# Обзор архитектуры AI-Breadboard

## Введение

**AI-Breadboard** — это интерактивная тестовая среда для исследования, прототипирования и сравнения современных языковых моделей искусственного интеллекта. Архитектура системы спроектирована по принципу «макетной платы» (breadboard), где различные модели ИИ выступают в роли сменных компонентов, подключаемых через единую шину (UnifiedChatModel).

## Основные принципы проектирования

### 1. Унификация интерфейсов

Все модели независимо от источника (облачные API, локальные серверы, локальный инференс) доступны через **единый интерфейс** `UnifiedChatModel`. Это позволяет разработчикам:

- Быстро переключаться между моделями без изменения кода
- Экспериментировать с разными провайдерами
- Сравнивать результаты в реальном времени

```
┌──────────────────────────────────────────┐
│    Приложение / Пользователь            │
└──────────────────┬───────────────────────┘
                   │
                   ▼
        ┌──────────────────────┐
        │ UnifiedChatModel     │
        │ (Единая шина)        │
        └─────────┬────────────┘
                  │
         ┌────────┴─────────┬─────────────────┐
         │                  │                  │
    ┌────▼─────┐    ┌───────▼────┐    ┌──────▼────┐
    │ Облачные │    │ Локальные  │    │ Локальный │
    │   API    │    │  серверы   │    │ инференс  │
    └──────────┘    └────────────┘    └───────────┘
```

### 2. Модульность

Система разделена на независимые модули, каждый из которых отвечает за определённую функцию:

- **AI-оркестратор** — управление моделями и провайдерами
- **RAG-система** — поиск по документам и контекстная память
- **Skills-система** — расширяемые навыки и плагины
- **Веб-интерфейс** — удобный пользовательский интерфейс
- **API-сервер** — REST и WebSocket интерфейсы

### 3. Гибкость и расширяемость

- Легко добавлять новых провайдеров через адаптеры
- Навыки (Skills) регистрируются динамически
- Система RAG поддерживает разные движки поиска
- Плагины расширяют функциональность

### 4. Наблюдаемость

- Структурированное логирование всех операций
- Контрольные точки для отладки
- SSE-потоки для мониторинга в реальном времени
- Полная трассировка вызовов между компонентами

## Слои архитектуры

Архитектура AI-Breadboard организована в четыре уровня:

```
┌─────────────────────────────────────────────────────┐
│              УРОВЕНЬ ИНТЕРФЕЙСОВ                    │
│  Веб-UI | CLI | API (REST/WebSocket)              │
└─────────────────────┬───────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────┐
│           УРОВЕНЬ ПРИЛОЖЕНИЯ                        │
│  Оркестратор | Маршрутизация | Бизнес-логика      │
└─────────────────────┬───────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────┐
│           УРОВЕНЬ СЕРВИСОВ                          │
│  RAG | Skills | TTS | Secrets | User Manager       │
└─────────────────────┬───────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────┐
│           УРОВЕНЬ ПОДКЛЮЧЕНИЙ                       │
│  Адаптеры провайдеров | Векторные БД | Кэши       │
└─────────────────────────────────────────────────────┘
```

### Уровень 1: Интерфейсы доступа

Представляет собой точки взаимодействия пользователя с системой:

- **Веб-интерфейс** (`src/fastapi/webinterface/`) — современный UI с чатом, поиском, агентами
- **CLI-интерфейс** (`assist.ps1`, `assist.cmd`, `manage_tools.py`) — командная строка для запросов
- **REST API** (`src/api/` / `/api/*`) — программный доступ
- **WebSocket** — потоковые обновления в реальном времени

### Уровень 2: Приложение

Центральная логика системы:

- **AI-оркестратор** (`src/ai/model_manager.py`) — управление жизненным циклом моделей
- **UnifiedChatModel** (`src/ai/unified_chat.py`) — единая шина общения
- **Маршрутизация запросов** — направление запросов нужному провайдеру
- **Обработка ошибок** — circuit breaker, retry, fallback

### Уровень 3: Сервисы

Специализированные модули для различных задач:

- **RAG-система** (`src/rag/`) — поиск похожих документов
- **Skills-система** (`src/skills/` и `.agents/skills/`) — каталог навыков
- **Plugins-система** (`src/plugins/` и `plugins/`) — динамические плагины
- **TTS** (`src/tts/`) — синтез речи
- **Управление секретами** (`src/secrets/`) — ключи и квоты
- **User Manager** (`src/user_manager/`) — профили пользователей

### Уровень 4: Подключения

Низкоуровневое взаимодействие с внешними системами:

- **Адаптеры провайдеров** — Google Gemini, OpenAI, Ollama, Foundry, Windows AI, AGY и т.д.
- **Векторные БД** — FAISS для поиска embeddings
- **Кэширование** — быстрый доступ к истории и результатам
- **Хранилища** — SQLite для структурированных данных

## Поток данных при обработке запроса

```
1. Пользователь вводит сообщение
                │
                ▼
2. Веб-интерфейс отправляет запрос на API
                │
                ▼
3. FastAPI-маршрутизатор парсит запрос
                │
                ▼
4. UnifiedChatModel анализирует префикс модели
                │
                ▼
5. Выбирается нужный адаптер провайдера
                │
                ▼
6. RAG-система извлекает контекст (опционально)
                │
                ▼
7. Skills-система применяет функции (опционально)
                │
                ▼
8. Провайдер обрабатывает запрос
                │
                ▼
9. Ответ кэшируется и логируется
                │
                ▼
10. Результат возвращается пользователю
```

## Ключевые компоненты

### 1. Model Manager (Менеджер моделей)

```python
class ModelManager:
    """Управляет жизненным циклом всех доступных моделей."""
    
    def get_available_models(self) -> List[str]:
        """Получить все доступные модели."""
    
    def is_model_available(self, model_id: str) -> bool:
        """Проверить доступность модели."""
    
    def get_model_info(self, model_id: str) -> Dict:
        """Получить информацию о модели."""
```

**Ответственность:**
- Загружает доступные модели при старте
- Отслеживает состояние моделей (рабочая/неработающая)
- Кэширует информацию для быстрого доступа
- Исключает неработающие модели из ротации

### 2. UnifiedChatModel (Унифицированный чат)

```python
class UnifiedChatModel:
    """Единая точка входа для всех моделей."""
    
    async def call(self, model: str, messages: List[Dict]) -> str:
        """Обработать запрос к модели."""
    
    def get_supported_models(self) -> List[str]:
        """Получить список поддерживаемых моделей."""
```

**Ответственность:**
- Парсит префикс модели (`gemini:`, `openai:`, и т.д.)
- Направляет запрос нужному адаптеру
- Обрабатывает ошибки и fallback
- Логирует все операции

### 3. RAG Engine (Движок поиска)

```python
class RAGEngine:
    """Поиск релевантных документов по запросу."""
    
    def add_documents(self, documents: List[str]) -> None:
        """Добавить документы в индекс."""
    
    def search(self, query: str, top_k: int = 5) -> List[str]:
        """Найти похожие документы."""
```

**Ответственность:**
- Индексирует документы в векторное пространство
- Выполняет семантический поиск
- Формирует контекст для моделей
- Управляет памятью индекса

### 4. Skills Registry (Реестр навыков)

```python
class SkillsRegistry:
    """Управляет доступными навыками системы."""
    
    def register_skill(self, skill: Skill) -> None:
        """Зарегистрировать новый навык."""
    
    def get_skill(self, name: str) -> Skill:
        """Получить навык по имени."""
    
    def list_skills(self) -> List[str]:
        """Получить список всех навыков."""
```

**Ответственность:**
- Динамическая регистрация навыков
- Валидация навыков перед регистрацией
- Управление зависимостями между навыками
- Кэширование метаданных навыков

## Безопасность и изоляция

### Управление секретами

- API-ключи хранятся в `.env` файле (не коммитятся)
- Доступ через `SecretManager` с логированием
- Ротация ключей для особо критичных API (Gemini)
- Квоты на использование API

### Изоляция контекста

- Каждый пользователь имеет отдельную сессию
- Контекст запроса не утекает между пользователями
- Логирование включает идентификатор сессии
- Ray для изоляции рабочих процессов

## Масштабируемость

### Горизонтальное масштабирование

- FastAPI сервер может быть развернут на нескольких машинах
- Redis для кэширования между инстансами
- Load Balancer для распределения нагрузки

### Вертикальное масштабирование

- Параллельная обработка на GPU/CPU
- Кэширование embeddings для RAG
- Batch-обработка запросов

## Откказоустойчивость

### Circuit Breaker

Если провайдер недоступен, система автоматически:

1. Записывает ошибку в лог
2. Отмечает провайдер как неработающий
3. Не отправляет на него новые запросы
4. Периодически проверяет восстановление

### Retry с exponential backoff

```python
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=2, max=10)
)
async def call_model(model_id: str, messages: List[Dict]) -> str:
    """Обработать запрос с автоматическим повтором."""
```

### Fallback стратегии

Если основная модель недоступна, система может:

1. Использовать резервную модель того же провайдера
2. Переключиться на другой провайдер
3. Использовать локальную модель
4. Вернуть ошибку пользователю с рекомендациями

## Производительность

### Оптимизация

- **Кэширование результатов** — часто используемые запросы кэшируются
- **Batch-обработка** — несколько запросов обрабатываются вместе
- **Lazy Loading** — модели загружаются по требованию
- **Префетчинг** — предварительная загрузка популярных моделей

### Мониторинг

- Метрики Prometheus для всех операций
- SSE-потоки для мониторинга в реальном времени
- Логи со временем выполнения каждого компонента
