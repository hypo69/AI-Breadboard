# Компоненты системы

Описание основных компонентов архитектуры AI-Breadboard и их взаимодействия.

## Основные компоненты

### 1. Model Manager (Менеджер моделей)

Компонент, отвечающий за управление жизненным циклом доступных моделей.

**Функции:**
- Загрузка информации о доступных моделях при старте системы
- Отслеживание состояния моделей (рабочая, неработающая, недоступная)
- Кэширование информации о моделях для быстрого доступа
- Исключение неработающих моделей из ротации
- Обновление статуса моделей в реальном времени

**Интерфейс:**
```python
get_available_models() -> List[str]
is_model_available(model_id: str) -> bool
get_model_info(model_id: str) -> Dict
```

### 2. UnifiedChatModel (Единая шина общения)

Центральный компонент, обеспечивающий единый интерфейс для всех моделей.

**Функции:**
- Парсинг префикса модели (gemini:, openai:, ollama: и т.д.)
- Маршрутизация запросов к нужному адаптеру провайдера
- Обработка ошибок с использованием circuit breaker паттерна
- Автоматические повторы (retry) при сбоях
- Логирование всех операций

**Интерфейс:**
```python
async call(model: str, messages: List[Dict]) -> str
get_supported_models() -> List[str]
```

### 3. RAG Engine (Движок поиска по документам)

Компонент для семантического поиска и извлечения контекста из документов.

**Функции:**
- Индексирование документов в векторное пространство
- Выполнение семантического поиска по схожести
- Формирование контекста для передачи моделям
- Управление памятью индекса
- Поддержка различных движков поиска (FAISS, Milvus и т.д.)

**Интерфейс:**
```python
add_documents(documents: List[str]) -> None
search(query: str, top_k: int = 5) -> List[str]
get_context(query: str) -> str
```

### 4. Skills Registry (Реестр навыков)

Компонент для управления расширяемыми навыками системы.

**Функции:**
- Динамическая регистрация новых навыков
- Валидация навыков перед регистрацией
- Управление зависимостями между навыками
- Кэширование метаданных навыков
- Выполнение навыков в контексте запроса

**Интерфейс:**
```python
register_skill(skill: Skill) -> None
get_skill(name: str) -> Skill
list_skills() -> List[str]
execute_skill(name: str, **kwargs) -> Any
```

### 5. Provider Adapters (Адаптеры провайдеров)

Компоненты для интеграции с различными источниками моделей.

**Поддерживаемые провайдеры:**
- **Google Gemini** — облачный API Google с ротацией ключей (см. подробнее: [gemini-provider.md](gemini-provider.md))
- **Gemini CLI** — интеграция с Google Gemini CLI
- **Antigravity (AGY)** — провайдер Antigravity SDK
- **Microsoft AI Foundry Local** — локальный рантайм Foundry
- **Ollama** — локальный сервер моделей
- **OpenAI / OpenAI-compat** — OpenAI, DeepSeek, LM Studio
- **Windows AI** — аппаратно-ускоренные нативные API Windows Copilot Runtime (DirectML / NPU)
- **ONNX Runtime / DirectML (Olive)** — модели на диске с ускорением GPU/NPU
- **Hugging Face** — локальные модели экосистемы Transformers

**Интерфейс адаптера:**
```python
async call(model: str, messages: List[Dict]) -> str
validate_credentials() -> bool
get_available_models() -> List[str]
```

### 6. User Manager (Менеджер пользователей)

Компонент для управления профилями и сессиями пользователей.

**Функции:**
- Управление профилями пользователей
- Отслеживание активных сессий
- Сохранение истории чатов
- Управление настройками пользователя
- Изоляция контекста между пользователями

### 7. Secrets Manager (Менеджер секретов)

Компонент для безопасного управления чувствительными данными.

**Функции:**
- Хранение API-ключей и учетных данных
- Управление ротацией ключей
- Логирование доступа к секретам
- Поддержка переменных окружения
- Интеграция с хранилищами секретов

### 8. Web Interface (Веб-интерфейс)

Компонент для взаимодействия пользователя через браузер.

**Функции:**
- Отправка сообщений в чат
- Отображение ответов моделей
- Поиск по документам
- Управление навыками
- Отслеживание статуса моделей

### 9. API Server (API-сервер)

Компонент, предоставляющий REST и WebSocket интерфейсы.

**Функции:**
- Обработка HTTP-запросов
- WebSocket для потоковых обновлений
- SSE (Server-Sent Events) для уведомлений
- CORS для межодоменных запросов
- Аутентификация и авторизация

## Типы взаимодействия

### Синхронное взаимодействие

Используется для:
- Парсинга запроса
- Маршрутизации
- Валидации

Пример:
```
Запрос → UnifiedChatModel → Парсинг → Выбор адаптера
```

### Асинхронное взаимодействие

Используется для:
- Обращения к моделям (может быть долгим)
- RAG-поиска
- Выполнения навыков

Пример:
```
async call(model, messages) → Ожидание ответа → Возврат результата
```

### Событийное взаимодействие

Используется для:
- Уведомлений об изменении статуса
- Логирования операций
- SSE-потоков к клиентам
