# Версионированный Document RAG и отслеживание состояния документов

## 1. Архитектура и концепция

Подсистема **версионированного Document RAG** в AI-Breadboard обеспечивает инкрементальную, темпоральную и неразрушающую индексацию документов. Она позволяет сканировать пользовательские каталоги (например, папку `Документы` или Google Диск, смонтированный в `G:\My Drive`), отслеживать изменения файлов с помощью вычисления хэша SHA-256 и хранить полную историю версий и чанков в едином векторном индексе.

```
Пользовательская директория (например, G:\My Drive или Документы)
       │
       ▼ (Сканирование и вычисление SHA-256)
┌─────────────────────────────────────────────────────────┐
│              Реестр версий документов                   │  Хранит время модификации (mtime), хэш,
│              (document_rag_meta.json)                   │  текущую версию и историю по каждому файлу.
└───────────────────────────┬─────────────────────────────┘
                            │
       ┌────────────────────┴─────────────────────────────────────┐
       ▼ (Файл добавлен или изменён)                              ▼ (Файл не изменился)
┌───────────────────────────────────────────────┐  ┌────────────────────────────────┐
│ 1. Маркировка старых чанков в индексе:        │  │ Пропуск чанкования             │
│    `is_latest = False`                        │  │ и векторизации                 │
│ 2. Создание новых чанков:                     │  │ (Нулевой расход CPU / токенов) │
│    `version = N + 1`                          │  └────────────────────────────────┘
│    `is_latest = True`                         │
│    `version_timestamp = mtime`                │
│    `content_hash = sha256`                    │
│ 3. Векторизация и добавление в единый индекс  │
└───────────────────────────┬───────────────────┘
                            ▼
┌────────────────────────────────────────────────────────────────────────┐
│                       Единый векторный индекс                          │
│  - doc.md#chunk_0#v1  (is_latest: false, ts: 1710000000, version: 1)   │
│  - doc.md#chunk_0#v2  (is_latest: true,  ts: 1712000000, version: 2)   │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. Принцип работы и ключевые механизмы

### 2.1. Идентификация чанков и версий
Каждый фрагмент текста (чанк) хранит метаданные своего происхождения:
- `chunk_id`: составной идентификатор формата `f"{doc_name}#chunk_{idx}#v{version}"`.
- `version`: целочисленный номер версии (1, 2, 3...).
- `version_timestamp`: Unix-метка времени модификации файла.
- `is_latest`: булевый флаг (`True` для актуальной версии, `False` для архивных/устаревших).
- `content_hash`: SHA-256 хэш содержимого файла, из которого получен чанк.

### 2.2. Инкрементальное сканирование директорий
При вызове метода `scan_and_index_directory(dir_path)`:
1. Вычисляется SHA-256 хэш каждого поддерживаемого файла (`.txt`, `.md`, `.json`, `.csv`, `.pdf`, `.py` и др.).
2. Сравнивается с записью в реестре метаданных:
   - **Новый файл**: регистрируется как `версия 1`, чанкуется, векторизуется и добавляется в индекс с `is_latest = True`.
   - **Измененный файл** (хэш изменился):
     - В существующих чанках этого документа флаг `is_latest` переключается в `False`.
     - Номер версии инкрементируется: `новая_версия = текущая_версия + 1`.
     - Новые чанки индексируются с `is_latest = True` и `version = новая_версия`.
     - **Старые чанки НЕ удаляются из индекса**, сохраняя полную хронологию.
   - **Неизмененный файл** (хэш совпадает): пропускается без повторной обработки.
   - **Удаленный файл**: помечается как `archived` с `is_latest = False`.

## 3. Режимы поиска и фильтрация версий

Поиск через метод `search()` поддерживает фильтрацию версий, что исключает конфликт устаревших данных при стандартных запросах, но позволяет проводить аудит истории при необходимости:

| Режим | Параметр `version_filter` | Описание |
|---|---|---|
| **Только актуальные** *(По умолчанию)* | `"latest"` | Возвращает результаты только из последней активной версии (`is_latest == True`). Защищает контекст LLM от противоречивых старых данных. |
| **Все версии** | `"all"` | Ищет по всему индексу, включая архивные версии. Используется для поиска хронологии изменений и сравнения версий. |
| **Конкретная версия** | `"v1"`, `"v2"`, `"1"`, `"2"` | Ограничивает поиск чанками строго указанной версии документа. |
| **Срез на дату (Point-in-Time)** | `"<float_timestamp>"` | Возвращает версии, действовавшие на момент указанного времени. |

## 4. Модели данных (`src/rag/document_rag.py`)

### `DocumentChunk`
```python
@dataclass
class DocumentChunk:
    chunk_id: str             # Идентификатор (например, "report.md#chunk_0#v2")
    doc_name: str             # Относительный путь или имя документа
    chunk_index: int          # Порядковый номер чанка в документе
    text: str                 # Текст чанка
    start_char: int           # Начальное смещение символов в файле
    end_char: int             # Конечное смещение символов в файле
    version: int = 1          # Номер версии документа
    version_timestamp: float  # Метка времени версии
    is_latest: bool = True    # Флаг актуальности
    content_hash: str = ""    # Хэш SHA-256
    meta: Dict[str, Any]      # Дополнительные метаданные
```

### `DocumentInfo`
```python
@dataclass
class DocumentInfo:
    name: str                 # Имя документа в реестре
    size_bytes: int           # Размер файла в байтах
    modified_at: float        # Время изменения
    status: str               # 'indexed', 'pending', 'error', 'archived'
    chunks_count: int         # Число чанков в текущей версии
    version: int              # Номер текущей версии
    is_latest: bool           # Активен ли документ
    content_hash: str         # Хэш SHA-256
    versions: List[Dict]      # Полная хронология версий документа
```

## 5. Примеры использования в коде

### Сканирование директории `G:\My Drive` и поиск:
```python
from pathlib import Path
from src.rag.document_rag import get_document_rag_manager

manager = get_document_rag_manager()

# 1. Сканирование и инкрементальная индексация папки Google Диска
scan_result = manager.scan_and_index_directory(
    dir_path=Path("G:/My Drive"),
    provider="local_tfidf",
    recursive=True
)
print("Результат сканирования:", scan_result)

# 2. Поиск только по актуальным версиям
latest_results = manager.search(
    query="финансовый отчет годовой бюджет",
    top_k=5,
    version_filter="latest"
)

# 3. Поиск по всем версиям (сравнение истории)
history_results = manager.search(
    query="финансовый отчет годовой бюджет",
    top_k=10,
    version_filter="all"
)

# 4. Просмотр истории версий конкретного документа
doc_history = manager.get_document_history("finance_report.md")
print("История версий документа:", doc_history["versions"])
```

## 6. REST API эндпоинты

### 1. Инкрементальное сканирование каталога
`POST /api/rag/scan-directory`
```json
{
  "directory_path": "G:\\My Drive",
  "provider": "local_tfidf",
  "recursive": true,
  "chunk_size": 500,
  "chunk_overlap": 50
}
```

### 2. Семантический поиск с фильтрацией по версиям
`POST /api/rag/search`
```json
{
  "query": "план разработки на 2026 год",
  "top_k": 5,
  "version_filter": "latest"
}
```
