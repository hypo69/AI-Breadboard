## Введение в субагенты

### Что такое динамический субагент?

**Subagent (Субагент)** — это дочерний фоновый агент, создаваемый главным агентом во время выполнения сложных задач для параллельной, изолированной или специализированной обработки подзадач.

### Сравнение компонентов системы

| Компонент | Скоуп / Назначение | Поведение |
| :--- | :--- | :--- |
| **Skill (Навык)** | База знаний, регламенты и сценарии в `SKILL.md` | Подгружается по запросу в контекст главного агента |
| **ReAct Agent** | Backend Python-класс (`src/ai/agents/`) | Исполняется на сервере FastAPI с инструментами LangChain |
| **Subagent** | Динамический фоновый агент (Antigravity Context) | Запускается в отдельном диалоговом контексте с выбором рабочей области и модели |

## Архитектура и жизненный цикл

```
┌─────────────────────────────────────────────────────────┐
  ГЛАВНЫЙ АГЕНТ (Parent Agent)                           
 ├─────────────────────────────────────────────────────────┤
 │ 1. define_subagent  ──> Создание типа субагента         │
 │ 2. invoke_subagent  ──> Запуск одного или нескольких   │
 │ 3. send_message     ──> Уточнение инструкций            │
 │ 4. Reactive Wakeup  ──> Приём готового результата       │
 └────────────────────────────┬────────────────────────────┘
                              │
               ┌──────────────┴──────────────┐
               ▼                             ▼
 ┌───────────────────────────┐ ┌───────────────────────────┐
 │ SUBAGENT 1                │ │ SUBAGENT 2                │
 │ (Role: Security Auditor)  │ │ (Role: Performance Tester)│
 │ Model: pro                │ │ Model: flash              │
 │ Workspace: branch         │ │ Workspace: share          │
 └─────────────────────────┘ └───────────────────────────┘
```

## Определение субагента (`define_subagent`)

Субагент регистрируется в системе с помощью инструмента `define_subagent`.

### Схема параметров

```json
{
  "name": "unique_subagent_name",
  "description": "Человекочитаемое описание назначения и условий использования субагента",
  "system_prompt": "Подробная системная инструкция, правила поведения и роль",
  "enable_write_tools": true,
  "enable_mcp_tools": true,
  "enable_subagent_tools": false
}
```

- **`enable_write_tools`**: При значение `true` дает субагенту доступ к созданию/редактированию файлов и запуску терминальных команд.
- **`enable_mcp_tools`**: Разрешает использование инструментов MCP (Model Context Protocol).
- **`enable_subagent_tools`**: Разрешает субагенту создавать собственных вложенных субагентов.

## Запуск и оркестрация (`invoke_subagent`)

После объявления субагент запускается вызовом `invoke_subagent`. Могут запускаться несколько субагентов одновременно в параллельном режиме.

```json
{
  "Subagents": [
    {
      "TypeName": "code_auditor",
      "Role": "Security & Vulnerability Scanner",
      "Prompt": "Просканируй папку src/auth/ на уязвимости OWASP Top 10.",
      "Model": "pro",
      "Workspace": "branch"
    }
  ]
}
```

## Общение и мониторинг (`send_message` & `manage_subagents`)

### Отправка сообщений (`send_message`)
Родительский агент передаёт указания или уточняющие данные по `conversationId`:
```json
{
  "Recipient": "18ca471b-subagent-id",
  "Message": "Дополнительно проверь валидацию JWT-токенов в header.py"
}
```

### Управление жизнедеятельностью (`manage_subagents`)
- `list` — Получить список всех активных субагентов и их статусов (`running`, `idle`, `waiting_for_input`, `errored`).
- `kill` — Принудительно завершить работу субагента.
- `kill_all` — Остановить всех субагентов текущего процесса.

## Режимы изоляции рабочей области (Workspace Modes)

При вызове субагента можно настроить уровень изоляции рабочей среды:

1. **`inherit` (по умолчанию)** — Работа в той же директории и ветке, что и родительский агент.
2. **`branch`** — Создаёт полностью изолированное рабочее окружение в отдельной Git-ветке. Изменения субагента не затрагивают основной код до явного мёрджа.
3. **`share`** — Создаёт рабочую область на базе Git worktree, позволяя независимо переключать ветки без полного копирования файлов.

---

## Выбор моделей (Model Selection)

Каждому субагенту можно назначить оптимальную модель в зависимости от сложности задачи:

- **`inherit`**: Модель родительского агента.
- **`flash_lite`**: Легковесная модель для простых задач поиска и валидации.
- **`flash`**: Быстрая модель для чтения файлов, рефакторинга и быстрых проверок.
- **`pro`**: Флагманская модель для глубокого анализа, сложного планирования и архитектурного аудита.

## Примеры использования

### Пример: Автоматизированный аудит безопасности кода

```python
# 1. Определение субагента-аудитора
define_subagent(
    name="security_auditor",
    description="Аудитор безопасности кода Python и API",
    system_prompt="Вы — эксперт по безопасности. Проверяйте код на уязвимости, SQL-инъекции, утечки ключей и ошибки валидации.",
    enable_write_tools=False
)

# 2. Запуск в фоновом режиме
invoke_subagent(
    Subagents=[
        {
            "TypeName": "security_auditor",
            "Role": "Auth Router Auditor",
            "Prompt": "Проверь все эндпоинты в src/api/router_auth.py",
            "Model": "pro"
        }
    ]
)
```
