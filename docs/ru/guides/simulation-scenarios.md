## Введение

Для качественного тестирования клиентских чатов агентства и проверки работы **Client RAG** используется цепочка из двух этапов:
1. **Первичный запрос (Trigger)** — система симуляции генерирует фиктивный документ и сохраняет его в персональную базу знаний клиента.
2. **Проверочные вопросы (RAG Verification)** — повторные вопросы, ответы на которые должны строго извлекаться из созданной записи.

## 🔄 Сквозной кросс-сценарный тест

Пример цепочки запросов в одной сессии:

```
1. Запрос: «Найди договор на покупку Porsche с Иваном Петровым»
   └── Симулятор создает ДКП № ДКП-АВТО-2026/04-201 (16.4 млн руб.) -> RAG.

2. Запрос: «Оформи страховку КАСКО для этого автомобиля»
   └── Симулятор создает Полис № POL-AUTO-2026-9032 -> RAG.

3. Запрос (через N сообщений): «По какому договору и за какую цену Петров купил Porsche?»
   └── Client RAG извлекает контекст:
       Ответ: «Автомобиль Porsche Cayenne GTS был приобретен по договору № ДКП-АВТО-2026/04-201 за 16 400 000 руб.»
```
