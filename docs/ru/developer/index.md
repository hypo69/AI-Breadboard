## 1. Введение и архитектура системы

**AI-Breadboard** — это интерактивный испытательный стенд («макетная плата») для исследования, сравнительного тестирования и динамической маршрутизации между различными рантаймами ИИ (Windows AI, Foundry Local, ONNX/DirectML, Ollama, Google Gemini, OpenAI-совместимые API).

```
┌──────────────────────────────────────────────────────────────────────────┐
│                         Web UI / Чат-клиент                              │
│     (HTML5 / CSS3 / Vanilla JS, Менеджер сессий, Визуализация RAG)       │
└────────────────────────────────────┬─────────────────────────────────────┘
                                     │ HTTP / SSE / WebSocket
┌────────────────────────────────────▼─────────────────────────────────────┐
│                          FastAPI Сервер приложений                       │
│ ┌──────────────────────┐ ┌──────────────────────┐ ┌────────────────────┐ │
│ │  /api/chat/sessions  │ │  /api/chat (Stream)  │ │  /api/rag / /auth  │ │
│ └──────────────────────┘ └──────────────────────┘ └────────────────────┘ │
└────────────────────────────────────┬─────────────────────────────────────┘
                                     │
┌────────────────────────────────────▼─────────────────────────────────────┐
│                    Слой оркестрации и маршрутизации                      │
│ ┌─────────────────┐  ┌──────────────────┐  ┌───────────────────────────┐ │
│ │ Опрос железа    │  │ Политики роутинга│  │ Многоуровневый RAG-поиск  │ │
│ └─────────────────┘  └──────────────────┘  └───────────────────────────┘ │
└────────────────────────────────────┬─────────────────────────────────────┘
                                     │
┌────────────────────────────────────▼─────────────────────────────────────┐
│                       Модульные провайдеры моделей                       │
│ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐  │
│ │ Google Gemini │ │ Foundry Local │ │ Ollama Engine │ │ ONNX/DirectML │  │
│ └───────────────┘ └───────────────┘ └───────────────┘ └───────────────┘  │
└──────────────────────────────────────────────────────────────────────────┘
```

### Основные компоненты:
- **`src/ai/providers/`**: Модульные пакеты под каждый движок инференса с собственным адаптером и английским `README.md`.
- **`src/fastapi/`**: Асинхронный сервер управления сессиями, авторизацией, стримингом ответов, TTS/STT и панелью управления.
- **`src/rag/`**: Векторизация, индексирование истории и диалогов, семантический поиск контекста.
- **`src/logger/`**: Централизованное структурированное логирование через `src.logger.logger`.
- **`src/config.py`**: Загрузка открытых настроек из `config.json` и изоляция приватных секретов в `.env`.

## 2. Фундаментальные инженерные стандарты

Все изменения в кодовой базе **ОБЯЗАНЫ** строго соответствовать стандартам [CODE_RULES.md](file:///.ai/instructions/rules/CODE_RULES.md) и [REUSE_RULES.md](file:///.ai/instructions/rules/REUSE_RULES.md):

| Принцип | Требование | Ошибочные примеры |
|---|---|---|
| **English Only** | Код, docstrings, комментарии, сообщения коммитов и документация пишутся строго на английском языке. | Комментарии или docstring на других языках в `.py` файлах. |
| **Fail-Fast & Early Return** | Проверка условий и мгновенный выход при невалидных данных. Отказ от глубокой вложенности `if/else`. | 4+ уровней вложенности условий. |
| **Категорический запрет дефолтного `None`** | В сигнатурах функций запрещено использовать `None` по умолчанию. Используются явные пустые типы (`str = ''`, `list = []`, `dict = {}`, `int = 0`). | `def fn(data: dict = None)` ❌ |
| **Конфигурация вместо Hardcode** | Сетевые адреса, порты, таймауты и пути считываются из `config.json` или переменных окружения. | `host = "http://localhost:8000"` в коде. |
| **Лимит 500 строк** | Объем функционального кода одного файла не должен превышать 500 строк (+15% запас). Монолиты разбиваются на подпакеты. | Monolithic файл на 1500 строк. |
| **Обязательный аудит переиспользования** | Поиск существующего кода в проекте (`grep_search`, `find_by_name`) перед написанием новых функций или UI. | Создание дублирующих утилит. |
| **Стандартное логирование** | Логирование ведется строго через `src.logger.logger`. Прямые вызовы `print()` запрещены. | `print("Error...")` ❌ |

## 3. Стандарты документирования (hypo69 Docblock)

### 3.1 Структура docstring
Каждая функция, метод и класс оформляются в соответствии со стандартом `hypo69 docblock`:

```python
def retrieve_user_context(user_id: str, query: str = '', limit: int = 5) -> list[dict]:
    """Retrieve indexed conversational context chunks for a specific user.

    Queries the vector store and historical sessions database to build
    a ranked list of relevant context snippets matching the query text.

    Args:
        user_id (str): Unique user identifier.
        query (str): Search query or current user message. Defaults to ''.
        limit (int): Maximum number of context items to return. Defaults to 5.

    Returns:
        list[dict]: List of context chunk dictionaries containing score and content.

    Raises:
        ValueError: If user_id is empty or invalid.

    Examples:
        >>> from src.rag.user_rag import retrieve_user_context
        >>> chunks = retrieve_user_context("user_123", "system settings", limit=3)
        >>> print(len(chunks))
        3
    """
```

### 3.2 Правило "One Document Per Module"
Каждая директория в `src/` обязана содержать `README.md` на английском языке с описанием:
- Назначения и зон ответственности модуля.
- Таблицы публичных классов, методов и функций.
- Примеров интеграции и зависимостей.

## 4. Протокол разработки через тестирование (TDD-doc-gen)

Разработка ведется по 6-шаговому циклу TDD:

1. **Анализ влияния (Impact Analysis) и Спецификация:**
   - Определение зависимостей и мест вызова функции.
   - Описание спецификации в документации и docstring.
2. **Реализация кода:**
   - Написание чистого кода без значений `None` по умолчанию.
3. **Создание исчерпывающих тестов:**
   - Покрытие сценариев: Happy Path, Edge Cases, Пустые коллекции, Граничные значения, Ошибки, Регрессия.
   - 100% комментирование каждой переменной, шага и утверждения (`assert`).
4. **Запуск и верификация:**
   - Запуск `pytest tests/test_<module>.py --cov`. Прохождение 100% тестов и покрытие >= 70%.
5. **Документирование директории:**
   - Создание/обновление `README.md` в папке модуля.
6. **Готовность к коммиту:**
   - Проверка путей и ссылок, логически завершенный коммит.

## 5. Пошаговые инструкции по добавлению функционала

### 5.1 Добавление нового AI-провайдера
1. Создать папку `src/ai/providers/<provider_name>/`.
2. Создать адаптер, наследующий `src.ai.providers.base.BaseModelProvider`:
   ```python
   from src.ai.providers.base import BaseModelProvider

   class CustomProvider(BaseModelProvider):
       """Adapter implementation for Custom AI engine."""
       
       def __init__(self, model_name: str = '', api_key: str = '') -> None:
           self.model_name = model_name
           self.api_key = api_key

       async def ask(self, prompt: str) -> str:
           """Generate non-streaming response."""
           ...

       async def chat_stream(self, prompt: str, **kwargs):
           """Stream tokens iteratively."""
           yield "token"
   ```
3. Добавить схему настроек в `src/config.py` и зарегистрировать префикс провайдера в `src/fastapi/router_chat.py`.
4. Создать `src/ai/providers/<provider_name>/README.md`.
5. Написать модульные тесты в `tests/test_<provider_name>.py`.

### 5.2 Добавление нового API эндпоинта (FastAPI)
1. Объявить Pydantic-схемы запроса/ответа.
2. Реализовать асинхронный обработчик в соответствующем роутере:
   ```python
   @router.post('/items')
   async def handle_create_item(payload: FeaturePayload, request: Request):
       """Create and persist item record."""
       try:
           result = await asyncio.to_thread(service_method, payload.item_id)
           return {"status": "success", "data": result}
       except Exception as ex:
           logger.error(f"Error creating item {payload.item_id}: {ex}")
           raise HTTPException(status_code=500, detail=str(ex))
   ```
3. Написать тесты с использованием `TestClient`.

### 5.3 Расширение веб-интерфейса и синхронизация
1. Модули фронтенда размещаются в `src/fastapi/webinterface/`.
2. Использовать двухуровневую модель персистентности:
   - Синхронное сохранение в `localStorage` для мгновенного отклика интерфейса.
   - Фоновая асинхронная синхронизация с REST API сервера (`/api/...`).
   - Сохранение работоспособности в оффлайн-режиме при временной недоступности сервера.

## 6. Стандарты написания тестов и комментариев

В тестах каждая переменная и шаг должны быть детально прокомментированы:

```python
def test_session_creation_with_valid_payload():
    """Test saving a new chat session to SQLite database."""
    # --- Arrange: Подготовка входных данных ---
    test_session_id: str = "session_101"
    session_payload: dict = {
        "id": test_session_id,
        "title": "Architecture Discussion",
        "createdAt": 1740000000000,
        "updatedAt": 1740000000000,
        "messages": []
    }

    # --- Act: Выполнение операции в базе данных ---
    saved_session = chat_sessions_db.save_session(session_payload, user_id="user_1")

    # --- Assert: Проверка результата ---
    assert saved_session["id"] == test_session_id, (
        f"Expected session id '{test_session_id}', got '{saved_session.get('id')}'"
    )
```

## 7. Чек-лист перед коммитом (Pre-Commit Checklist)

Перед выполнением коммита проверьте:

- [ ] **Аудит переиспользования**: поиск аналогов в проекте выполнен (`REUSE_RULES.md`).
- [ ] **Языковой стандарт**: весь код, docstrings, комментарии и тесты строго на **английском языке**.
- [ ] **Docstrings**: все публичные сущности имеют `hypo69 docblock` с секциями `Args:`, `Returns:`, `Exceptions:`, `Examples:`.
- [ ] **Отсутствие `None` по умолчанию**: в сигнатурах нет `param = None`.
- [ ] **Логирование**: используется `src.logger.logger` (нет вызовов `print()`).
- [ ] **README в директориях**: в каждой новой папке создан английский `README.md`.
- [ ] **Тесты пройдены**: `pytest tests/ --cov` проходит успешно с требуемым покрытием.
