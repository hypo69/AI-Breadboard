# Жизненный цикл приложений в AI Breadboard

Архитектура AI Breadboard построена на принципе **«Hub & Spoke» (Ядро и Периферия)**, что обеспечивает модульность, масштабируемость и простоту обслуживания системы.

## Алгоритм обработки запроса

Любое взаимодействие с приложением (например, `/apps/windows`) следует строгому алгоритму обработки запроса:

1.  **Инициация:** Пользователь через UI или CLI инициирует действие.
2.  **Маршрутизация (API Gateway):** Запрос поступает на FastAPI-сервер.
3.  **Делегирование (Hub):** Система направляет запрос в соответствующий модуль `/apps/`.
4.  **Исполнение (Spoke/Core):** Приложение выполняет бизнес-логику, обращаясь к ядру (`src/`) или аппаратному обеспечению.
5.  **Ответ:** Результат сериализуется в JSON и возвращается пользователю.

## Пошаговое объяснение

| Этап | Действие | Зачем это происходит |
| :--- | :--- | :--- |
| **1. Инициация** | Пользователь нажимает кнопку или вводит команду. | Входная точка для изменения состояния системы. |
| **2. API Gateway** | FastAPI перехватывает HTTP-запрос. | Единый шлюз для безопасности, валидации и авторизации. |
| **3. Делегирование** | Вызов метода конкретного приложения из `/apps/`. | Отделение логики маршрутизации от бизнес-логики приложения. |
| **4. Исполнение** | Приложение вызывает `SystemCollector` или другие модули `src/`. | Обеспечение переиспользуемости кода и единства данных. |
| **5. Ответ** | Формирование JSON-ответа и передача его в UI/CLI. | Завершение цикла обработки запроса и обновление состояния пользователя. |

## Роль API-эндпоинтов

API-эндпоинт в AI Breadboard — это **контракт** между асинхронным интерфейсом (UI) и синхронной средой исполнения (Python/OS).

### Когда вызывается эндпоинт?
*   **Инициализация данных:** При загрузке страницы UI для отрисовки текушего состояния.
*   **Интерактивные действия:** При каждом взаимодействии пользователя с инструментами (запуск сканирования, обновление конфигурации).
*   **Реальное время:** При необходимости обмена данными между фронтендом и бэкендом для обновления метрик.

### Зачем вызывается эндпоинт?
1.  **Изоляция:** Фронтенд не знает, как устроена Windows API или другие подсистемы — он работает только с JSON.
2.  **Безопасность:** Эндпоинт фильтрует входные данные и контролирует доступ к системным ресурсам.
3.  **Наблюдаемость:** Единая точка входа позволяет логировать все действия через `src.logger.logger`.

## Детализация процесса делегирования (Этап 3)

Процесс делегирования — это не просто вызов функции, а архитектурный мост, обеспечивающий чистоту кода:

1.  **Регистрация маршрутов (`src/app/__init__.py`):** При старте приложения FastAPI сканирует этот файл, чтобы привязать URL-пути (например, `/api/windows/scan`) к соответствующим маршрутизаторам (`APIRouter`).
2. **Обработка зависимости (Dependency Injection - DI):** Эндпоинт FastAPI при получении запроса проверяет, какие зависимости требуются для выполнения логики (используя конструкцию `Depends()`).
   *   **Зачем это нужно:** Вместо того чтобы внутри функции эндпоинта вручную создавать экземпляры классов (например, `collector = WindowsCollector()`), что привело бы к жесткой связанности, мы просим FastAPI «внедрить» уже подготовленный экземпляр.
   *   **Как это работает:**
       *   При старте системы фабричные функции или провайдеры регистрируют объекты в контейнере зависимостей FastAPI.
       *   Когда приходит запрос, FastAPI смотрит на сигнатуру функции-обработчика, видит `app: WindowsApp = Depends(get_windows_app)`, находит функцию `get_windows_app`, вызывает её (если объект еще не создан или требуется новый) и передает готовый, сконфигурированный экземпляр `WindowsApp` в обработчик.
   *   **Преимущество:** Это гарантирует, что приложение (`Spoke`) получает корректно настроенное окружение, доступ к конфигурации и подключениям к ядру (`src/`), при этом код эндпоинта остается максимально лаконичным и сфокусированным только на обработке HTTP-запроса.

3.  **Вызов интерфейса:** Маршрутизатор вызывает стандартизированный метод (например, `handle_request()` или `run_action()`) внутри класса приложения в `/apps/`.
4.  **Слой абстракции:** Сам маршрутизатор FastAPI содержит минимум логики: он лишь проверяет параметры запроса (валидация через Pydantic) и передает их в бизнес-логику приложения.

Этот подход гарантирует, что если логика приложения (например, `/apps/windows/core/collector.py`) изменится, API-слой останется неизменным.

---

> [!NOTE]
> Все новые приложения в `/apps` **должны** следовать этому протоколу и регистрироваться в `src/app/__init__.py` согласно стандартам `CODE_RULES.md`.
