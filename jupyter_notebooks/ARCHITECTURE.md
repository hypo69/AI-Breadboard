# 🏗️ Hybrid RAG Architecture: Colab Index Generation\n\n## Overview\n\nThe `PixelRAG_Hybrid_Index_Generator.ipynb` notebook implements a complete pipeline for generating searchable indices from documents using Google Colab's GPU/TPU resources. It creates **two parallel indices** for different types of content:\n\n```\nSOURCE DOCUMENTS (in Google Drive)\n         │\n         ├─→ PDF Files ────┐\n         ├─→ Images ───────┼──→ PIXEL PROCESSING\n         └─→ Text Files ───┤\n                           │\n                    Extract Tiles + Metadata\n                           │\n                           ▼\n                    [Image Embedder]\n                           │\n                           ▼\n                    [FAISS Visual Index]\n                           │\n         ┌─────────────────┴──────────────┐\n         │                                 │\n      TEXT RAG                         PIXEL RAG\n    (Semantic Text)                   (Visual Search)\n         │                                 │\n      FAISS Index                      FAISS Index\n         │                                 │\n         └────────────┬────────────────────┘\n                      │\n                OUTPUT: rag_indices.zip\n```\n\n---\n\n## Component Architecture\n\n### 1️⃣ Input Processing\n\n**Supported Formats:**\n- **Text:** `.txt`, `.md`, `.json`, `.csv`, `.py`, `.js`, `.html`\n- **Structured:** PDFs, images (PNG, JPEG, GIF, WebP)\n- **Metadata:** File paths, timestamps, source tracking\n\n**Processing:**\n```\nDocument File\n    ↓\n[Format Detection]\n    ↓\n[Content Extraction]\n    ├─→ PDF → Text + Pages as Images\n    ├─→ Image → Direct tile (no processing)\n    └─→ Text → Direct extraction\n    ↓\n[Chunking / Tiling]\n    ├─→ Text: 500-char overlapping chunks\n    └─→ Images: Resized to 1024x1024 tiles\n```\n\n### 2️⃣ Text RAG Pipeline\n\n```\nText Chunks (500 chars each)\n    │\n    ├─→ [TF-IDF Vectorization]\n    │   • Build vocabulary\n    │   • Calculate IDF weights\n    │   • Generate normalized vectors\n    │\n    ├─→ [Semantic Embedding]\n    │   • Model: sentence-transformers/all-MiniLM-L6-v2\n    │   • Dimension: 384\n    │   • Batch size: 32\n    │\n    └─→ [FAISS Index]\n        • Index type: FlatL2\n        • Metric: L2 distance (Euclidean)\n        • Searchable immediately after build\n\nOutput: \n  ├─ index.faiss (binary FAISS index)\n  ├─ chunks.jsonl (metadata per chunk)\n  ├─ vectors.npy (NumPy array of embeddings)\n  ├─ vocab.json (vocabulary mapping)\n  ├─ idf.json (IDF weights)\n  └─ metadata.json (configuration)\n```\n\n### 3️⃣ Pixel RAG Pipeline\n\n```\nSource: PDF Pages + Images\n    │\n    ├─→ [PDF Extraction]\n    │   • Convert each page to PNG image\n    │   • Preserve page numbers\n    │   • Resolution: ~150 DPI\n    │\n    ├─→ [Image Processing]\n    │   • Resize to 1024x1024 (preserving aspect ratio)\n    │   • Convert to RGB\n    │   • Save as PNG tiles\n    │\n    ├─→ [Visual Embedding]\n    │   • Model: CLIP (openai/clip-vit-base-patch32)\n    │   • Input: Image tile\n    │   • Output: 512-dim vector\n    │   • Alternative: Use image feature vectors\n    │\n    └─→ [FAISS Index]\n        • Index type: FlatL2\n        • Metric: L2 distance\n        • Metadata: Image path, source, page#\n\nOutput:\n  ├─ index.faiss (visual FAISS index)\n  ├─ chunks.jsonl (image metadata)\n  ├─ tiles/ (cached PNG images)\n  │   ├─ document_page_1.png\n  │   ├─ document_page_2.png\n  │   └─ image_processed.png\n  └─ metadata.json (configuration)\n```\n\n### 4️⃣ Metadata Management\n\n**Text Chunk Metadata:**\n```json\n{\n  \"chunk_id\": \"document.md#chunk_5\",\n  \"doc_name\": \"document.md\",\n  \"chunk_index\": 5,\n  \"text\": \"...\",\n  \"start_char\": 2500,\n  \"end_char\": 3000,\n  \"version\": 1,\n  \"version_timestamp\": 1695384000.0,\n  \"is_latest\": true,\n  \"content_hash\": \"abc123def456\",\n  \"meta\": {\n    \"source_file\": \"/path/to/document.md\",\n    \"source_type\": \"text\",\n    \"doc_type\": \".md\"\n  }\n}\n```\n\n**Pixel Chunk Metadata:**\n```json\n{\n  \"chunk_id\": \"manual#page_5\",\n  \"source_type\": \"pdf\",\n  \"source_path\": \"/path/to/manual.pdf\",\n  \"page_number\": 5,\n  \"image_path\": \"/tiles/manual_page_5.png\",\n  \"image_dimensions\": [1024, 768],\n  \"version\": 1,\n  \"version_timestamp\": 1695384000.0,\n  \"is_latest\": true,\n  \"content_hash\": \"xyz789abc123\",\n  \"meta\": {...}\n}\n```\n\n---\n\n## Execution Flow in Colab\n\n### Cell-by-Cell 50 MB)\n  screenshots/ (20 PNG files, 30 MB)\n  README.md (50 KB)\n\n    ↓\n    \n[Extract Phase]\n  • PDF → 200 image tiles (1 per page)\n  • PDF → Full text (OCR extraction)\n  • PNGs → 20 image tiles (resized)\n  • MD → 100 text chunks\n  \n    ↓\n    \n[Vectorize Phase]\n  • 100 text chunks → 100 × 384-dim vectors (TF-IDF)\n  • 220 image tiles → 220 × 512-dim vectors (CLIP)\n  \n    ↓\n    \n[Index Phase]\n  • Text vectors → FAISS FlatL2 index (100 docs)\n  • Image vectors → FAISS FlatL2 index (220 docs)\n  • Both indices searchable via L2 distance\n  \n    ↓\n    \nOUTPUT: rag_indices.zip (150 MB)\n  ├─ text_rag/\n  │  ├─ index.faiss (5 MB, 100 chunks)\n  │  ├─ chunks.jsonl (metadata)\n  │  └─ vectors.npy (embedded vectors)\n  │\n  └─ pixel_rag/\n     ├─ index.faiss (8 MB, 220 chunks)\n     ├─ tiles/ (130 MB, 220 PNG files)\n     └─ chunks.jsonl (metadata)\n```\n\n---\n\n## Search Workflow (After Index Generation)\n\nOnce indices are deployed locally:\n\n```\nUser Query: \"How to configure the system?\"\n    │\n    ├─→ [Text RAG] \n    │   1. Embed query → 384-dim vector\n    │   2. FAISS search (L2 distance)\n    │   3. Return top-5 text chunks\n    │   \n    ├─→ [Pixel RAG]\n    │   1. Embed query → 512-dim vector (conceptual)\n    │   2. FAISS search (L2 distance)\n    │   3. Return top-5 image tiles\n    │   \n    └─→ [Router Decision]\n        • Query contains visual keywords?\n        • Should use both indices?\n        • Merge results with scores\n        \n        └─→ [RAG Context]\n            • \"Configuration section found on page 15 (image)\"\n            • \"Setup instructions: (text chunk from manual)\"\n```\n\n---\n\n## Performance Characteristics\n\n### Build Time (Colab GPU)\n\n| Documents | Text Chunks | Pixel Tiles | Time |\n|---|---|---|---|\n| 10 files (50 MB) | 100 | 50 | 10 min |\n| 50 files (200 MB) | 400 | 200 | 30 min |\n| 100 files (500 MB) | 1000 | 500 | 60 min |\n\n### Search Time (Local)\n\n| Index Size | Query Time | Memory Used |\n|---|---|---|\n| 100 chunks | < 1 ms | 50 MB |\n| 1000 chunks | 5 ms | 200 MB |\n| 10000 chunks | 50 ms | 1 GB |\n\n### Storage\n\n```\nInput Documents: 200 MB\n  ↓ (after extraction + vectorization)\nOutput ZIP: 150 MB\n  • FAISS indices: 20 MB (highly compressed vectors)\n  • Image tiles: 100 MB (PNG cached)\n  • Metadata: 1 MB (JSON)\n  • Vectors: 10 MB (NumPy arrays)\n```\n\n---\n\n## Key Design Decisions\n\n### 1. Why Two Separate FAISS Indices?\n**Reason:** Different vector dimensions and use cases\n- Text: 384-dim (semantic meaning)\n- Pixel: 512-dim (visual features)\n- Separate indices allow independent optimization\n\n### 2. Why L2 Distance (Not Cosine)?\n**Reason:** FAISS FlatL2 is faster for small indices\n- Vectors are normalized → L2 ≈ Cosine\n- Better for Colab constraints\n- Can easily migrate to IVF for large datasets\n\n### 3. Why Batch Processing?\n**Reason:** Memory efficiency\n- Batch size 32 balances speed vs memory\n- Prevents OOM on 16 GB Colab GPU\n- Can be adjusted in Cell 0\n\n### 4. Why Store Tiles?\n**Reason:** Reusability and caching\n- Tiles are expensive to regenerate\n- Cached tiles enable fast re-indexing\n- Portable across different machines\n\n---\n\n## Future Enhancements\n\n```\nv1.0 (Current)\n├─ Text RAG (TF-IDF + FAISS)\n├─ Pixel RAG (Image tiles + FAISS)\n└─ Local FAISS index\n\nv1.1 (Planned)\n├─ Query Router (text vs visual detection)\n├─ Hybrid search (both indices)\n└─ LLM integration (context generation)\n\nv2.0 (Future)\n├─ Incremental indexing\n├─ IVF indices (1M+ documents)\n├─ Qdrant integration\n├─ Web URL support\n└─ OCR for scanned PDFs\n```\n\n---\n\n## References\n\n- [FAISS Documentation](https://github.com/facebookresearch/faiss)\n- [Sentence Transformers](https://www.sbert.net/)\n- [Google Colab GPU](https://colab.research.google.com/notebooks/gpu.ipynb)\n- [PDF Processing in Python](https://github.com/pdfminer/pdfplumber)\n- [PIL Image Processing](https://pillow.readthedocs.io/)\n\n---\n\n**For more details, see:**\n- [Quick Start](./QUICK_START.md)\n- [Document Preparation](./PREPARE_DOCUMENTS.md)\n- [Main README](./README.md)\n
